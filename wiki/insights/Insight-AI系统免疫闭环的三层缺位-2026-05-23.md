# Insight：AI 系统免疫闭环的三层缺位

## 碰撞来源

三篇风马牛不相及的文章：游戏工作室的 Hooks 机制、Agent 自学习复盘模式、Codex 的跨会话 Memory 与长期 Automation。

## 洞见

生物免疫系统由三层构成：**感知异常**（发现入侵）→ **记忆编码**（形成抗体）→ **持续巡检**（定期清查残余）。把这三层映射到 AI 系统：

| 生物免疫层 | AI 系统对应 | 现有工具实现 |
|----------|------------|------------|
| 感知异常 | Hooks：在 commit/push/会话节点自动触发诊断 | CCGS 的 12 个 Hooks |
| 记忆编码 | 错误知识卡片：将纠正行为结构化存储 | [[自学习复盘模式]] 的 self-improving-agent |
| 持续巡检 | 长期 Automation：自主唤醒执行定期健康任务 | [[Codex-全能助手]] 的 Automation 机制 |

**问题在于：这三层在现有工具中彼此孤立。**

CCGS 的 Hooks 能在流程节点捕获异常，但不会将异常编码为持久的经验卡片——它记录日志，但不学习。自学习复盘模式能生成卡片，但依赖"被纠正时触发"，对 Hooks 捕获的结构性失败视而不见。Codex 的 Automation 能调度长期任务，但其记忆层是个人偏好导向的，不是系统健康导向的。

三层之间没有信号通道。

## 缺位的结构

一个真正具备免疫能力的 AI 系统，应该有如下闭环：

```
Hooks（结构性感知）
  → 失败事件路由到错误经验卡片库
      → 卡片触发 Skill 层自动修复（self-evolving-skill）
          → Automation 调度验证任务确认修复有效
              → 验证结果更新卡片可信度
                  → 返回 Hooks 监控下一次同类事件
```

这不是科幻，是把三个已存在的机制用一个消息总线串联起来的工程问题。

## 当前工具的最近邻

[[做梦机制]] 在 wiki-compiler 层面是这个闭环的不完整版本：健康检查（感知）→ Insight 生成（记忆）→ 定时 cron 触发（调度）。但它只覆盖知识库健康，不覆盖 Agent 行为健康。

[[安全体系的自进化闭环]] 从安全维度触及了相近问题，但同样没有把感知→记忆→调度三层打通。

## 实践方向

若要构建这个闭环，最小实现路径是：
1. 在 CLAUDE.md 的 Hooks 中，将"失败事件"结构化输出到固定格式的错误日志
2. 做梦机制（或 cron）定期读取错误日志，批量生成纠正卡片
3. 纠正卡片的格式与 self-improving-agent 兼容，由 Agent 在后续任务中主动检索

这三步不需要新工具，只需要三个现有机制之间约定一种共同格式。
