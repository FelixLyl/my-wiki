# Agent 行为图谱是安全审计的结构底座

## 核心洞见

安全审计在传统软件中是规则集（blocklist + allowlist），在高权限 Agent 中本质上是一个**图遍历问题**：Agent 的每一次工具调用都是一条有向边，调用链构成可遍历的行为图谱。只有当这张图是可见的，审计才有着力点。

## 三篇文章的碰撞

[[OpenClaw-Agent安全体系]] 的零信任体系列出了四道防线（Skill 供应链 → 运行时拦截 → 密钥管理 → Prompt Injection 防御），但这四层是**独立模块**，缺少统一的结构底座——没有办法回答"这次 Agent 运行，总共经过了哪些节点，危险操作在哪条路径上出现"。

[[Graphify-代码知识图谱]] 提供了这个结构底座的技术原型：用实体 + 关系的图结构替代扁平文档，使代码库从"一堆文件"变为"可查询的关系网络"。Graphify 的核心能力是路径追踪（`path` 命令显示从论文节点到代码节点的完整图谱路径）和社区发现（识别模块聚类）。

[[claude-code-source-study]] 揭示了 Claude Code 源码层的证据：BashTool 的"四层安全防线"、27 事件 Hooks 系统、AsyncGenerator 对话循环状态机。这些设计在实现层面已经隐含了行为图谱的结构——每次工具调用触发 Hook，状态机维护调用序列。**这些数据已经存在，只是没有被图化**。

## 结构推论

一个完整的 Agent 安全审计系统需要三层：

| 层次 | 来源 | 功能 |
|------|------|------|
| 行为捕获层 | Hook 系统 + 调用日志 | 将每次工具调用记录为图的一条有向边 |
| 图构建层 | Graphify 式图引擎 | 将调用序列构建为可查询的有向图 |
| 审计层 | 零信任规则映射到图遍历 | 在图上检测"危险路径模式"而非逐操作检查 |

在这个结构里，[[OpenClaw-Agent安全体系]] 的四道防线变成了图上的**路径断点**：`openclaw-ops-guardrails` 的拦截点 = 图中特定边的访问控制，Prompt Injection 防御 = 检测图中外部节点是否异常连接到高权限操作节点。

## 实践意义

1. **审计可解释**：图结构天然支持"为什么这次操作被拦截"——展示触发拦截的路径即可，而非只返回 block reason
2. **攻击面可视**：Skill 供应链攻击在图上表现为"新节点接入高权限核心节点"，可触发自动警报
3. **做梦机制的镜像**：[[Insight-安全审计即做梦机制的镜像-2026-04-16]] 指出安全审计与知识整理是同构操作。补全：两者的共同底座都是**对已发生行为的图化遍历**，知识做梦是对知识图谱的遍历，安全审计是对行为图谱的遍历

## 局限

当前此路径仍是概念层面。落地需要解决：
- Agent 调用日志的结构化采集（格式标准化）
- 图引擎对实时流式调用的支持（Graphify 目前是静态代码库分析）
- 审计规则的图化表达（从 blocklist 到 graph pattern）
