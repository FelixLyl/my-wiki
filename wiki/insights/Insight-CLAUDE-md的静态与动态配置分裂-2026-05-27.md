# CLAUDE.md 的静态与动态配置分裂

## 碰撞来源

三篇风马牛不相及的文章读完后，有一个裂缝浮出来：

- [[Claude-Code源码架构]] 揭示 CLAUDE.md 在产品内部以"声明层"方式参与 5+1 层配置合并，System Prompt 里的静态规范作为 Prompt Cache 前缀，动态注入的项目配置按优先级排列
- [[CLAUDE-md配置方法论]] 强调"只写 Claude 自己推断不出来的规则"，控制在 200 行以内，每行都要经过失败验证
- [[自学习复盘模式]] 描述 Agent 把纠正经验自动整理成知识卡片，写入记忆库，供后续任务检索

裂缝在此：CLAUDE.md 是写死的静态配置，但 Agent 的纠错经验是实时产生的动态知识。两者分开存放，互不相连。

## 洞见

CLAUDE.md 当前的角色是"初始化时的行为契约"，Karpathy 准则、黄金四条、Skill 裁决规则，这些都是项目开始前人工写入的规范。而自学习复盘模式产生的知识卡片存入记忆库，与 CLAUDE.md 平行运行，共享 Claude 的注意力但互不通信。

这造成一个浪费：当 Agent 从错误中学到"不要用推测性功能"这条规则后，这条规则存在于记忆库里，下次任务要靠检索才能调用。但同样一条规则，如果写进 CLAUDE.md，则在每次任务开始时自动加载，无需检索。

源码层的 5+1 合并系统天然支持多来源配置注入，但"自动把纠错经验写进 CLAUDE.md"这一步从未被设计。配置进化的通道存在，只是没有人往里倒东西。

## 架构机会

把[[自学习复盘模式]]中的知识卡片生成流程，接到 CLAUDE.md 的更新流程上：

1. Agent 被纠正 → 结构化知识卡片（错误描述 + 正确做法 + 适用场景）
2. 定期（或达阈值时）：过滤出高可信卡片（人工纠正来源），以"已验证规则"格式追加到 CLAUDE.md
3. CLAUDE.md 自动压缩（超过 200 行时合并重复规则、淘汰低频规则）
4. 形成闭环：每次任务不只执行，还在给 CLAUDE.md 做"失败验证"

这意味着 CLAUDE.md 从"初始化文档"变成"持续进化的行为约定"，其价值随项目使用时长增加而增加——而不是在项目开始时写一遍之后就很少动了。

## 约束

- 自动写入 CLAUDE.md 的规则必须有人工验证标注，避免 Agent 把错误经验写成新规范
- 卡片精简原则不变：只写推断不出的规则，进入 CLAUDE.md 的门槛高于进入记忆库的门槛
- 这不是让 Agent 无限扩充配置，而是让"已验证失败经验"有一个结构化的上升通道
