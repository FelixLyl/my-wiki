# 可视化是自主 Agent 安全体系中缺失的透明度层

Agent 的执行能力越强，人类对其行为的感知能力就越弱。当前的安全讨论集中在拦截（供应链扫描、高危操作二次确认）和防御（零信任、最小权限），却几乎不涉及一个更根本的问题：如何让 Agent 的执行路径对人类保持可读。

## 三篇文章揭示的共同缝隙

**Markdown查看器技能**揭示了一个现象：当 Agent 能够用图表表达复杂结构（依赖树、调用图、架构分层），人类理解 Agent 意图的成本骤降。这不是展示功能，而是认知接口。

**Claude Code 源码研究**描述了 Claude Code 内部的安全机制：BashTool 四层防线、七种权限模式、27 事件 Hooks 系统。这些机制均存在于代码层，对日常使用者不可见。一个普通用户无法在不读源码的情况下理解 Agent 当前处于哪个权限模式、哪个 Hook 触发了什么动作。

**OpenClaw Agent 安全体系**指出了安全的优先部署顺序：供应链扫描 → 运维护栏 → 密钥管理 → 定期巡检。该体系完整，但缺少一个维度：让人类实时感知 Agent 正在做什么、已经做了什么、下一步打算做什么。

## 透明度是安全的前置条件

现有安全体系假设人类能在"审批节点"介入（高危操作二次确认）。但审批的质量依赖信息质量：如果人类看不清 Agent 即将执行什么、为什么执行，审批就退化为橡皮图章。

可视化 Skill 提供了一条不同路径：在 Agent 执行前，将执行计划渲染为可读图（流程图、依赖图、权限树），人类审批的对象从"一条命令"升级为"一张可理解的执行意图图"。

这一思路在 Claude Code 源码中有结构性支撑：27 事件 Hooks 系统为每个关键执行节点提供了介入点，配合图表渲染 Skill，理论上可以构建出 Agent 执行路径的实时可视化审计流。

## 洞见

安全体系的当前盲点是：它能阻止 Agent 做坏事，但无法帮助人类理解 Agent 在做什么。透明度不是安全的附属功能，而是前置条件。图表生成能力（如 markdown-viewer/skills 提供的调用图、依赖树、架构图）应被纳入 Agent 安全体系的标准工具集，作为"意图可视化层"与拦截层并列存在。

一个自主 Agent 如果能在执行前主动生成一张人类可读的"行动计划图"，审批就不再是形式，安全就不再只是事后拦截。
