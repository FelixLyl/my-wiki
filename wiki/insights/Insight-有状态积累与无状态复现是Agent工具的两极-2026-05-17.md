# 有状态积累与无状态复现是Agent工具的两极

三个风马牛不相及的工具碰撞出一个分类框架：

- **Codex**：内置记忆预览版，每次对话后主动建议后续工作，全球 300 万开发者的使用模式正从"写代码"演进为"持续协作"
- **GBrain**：Brain-Agent Loop，信号到达→读取→回应→写入，"没有此循环的 Agent 永远从零开始"
- **HyperFrames**：`frame = floor(time * fps)`，确定性设计，同一输入永远产出相同输出，专为 CI 和自动化批量生产设计

表面上三者来自不同领域（代码助手/知识脑/视频渲染），但它们在根本设计哲学上分属两个对立端点：

## 有状态积累派（GBrain、Codex记忆层）

每次执行后世界更丰富。核心指标：知识密度随时间增长。
- GBrain 的 Timeline 只追加，Compiled Truth 随新证据更新
- Codex 记忆层跨 session 保留上下文，主动建议后续工作
- 价值在于"差异随时间复利增长"

## 无状态确定性派（HyperFrames、工具层通用原则）

相同输入永远相同输出。核心指标：可复现性和批量可信度。
- HyperFrames 的渲染管道刻意剔除随机性，适合 CI 流水线
- 无状态让工具可以安全地横向扩展、重试、并发
- 价值在于"任何时间点的结果都可信"

## 两极并非矛盾，而是层级分工

一个完整的 Agent 系统同时需要两极：

| 层级 | 哲学 | 典型工具 |
|------|------|---------|
| 知识层 | 有状态积累 | GBrain、wiki-compiler、Agent记忆 |
| 执行层 | 无状态复现 | HyperFrames、幂等 API、CI 工具 |
| 协作层 | 两者桥接 | Codex 记忆（选择性持久化执行经验） |

真正的设计失误是**错误地混用两极**：把执行层做成有状态（每次渲染结果不同）或把知识层做成无状态（Agent每次重新发现同样的东西）。前者让系统不可信，后者让系统永远不成长。

## 推论：幂等性是无状态层的基础，而非知识层的约束

[[幂等防重模式]] 描述的是知识层的增量编译策略（只处理新文件），这与无状态确定性不同——幂等防重的目标是"不重复产出"，而不是"相同输入相同输出"。幂等性在知识层的作用是防止冗余积累，而非追求可复现性。两者都叫"幂等"，但底层目标不同。
