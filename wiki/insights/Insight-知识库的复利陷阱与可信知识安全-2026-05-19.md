# Insight：知识库的复利陷阱——知识复利与知识污染的对称性

## 核心洞见

[[知识管理/GBrain-世界知识脑]] 和 [[人物/Andrej-Karpathy]] 都强调知识库的复利效应：持续积累的知识让 Agent 每天变得更聪明。然而这个逻辑存在一个对称的推论：**如果正确的知识可以复利增长，被污染的知识同样可以复利扩散。**

[[安全/OpenClaw-Agent安全体系]] 的零信任原则覆盖了"外部输入不可信"（Prompt Injection 防御），但对"已持久化的知识本身是否可信"尚无明确论述。这是一个结构性盲区。

## 碰撞分析

### 三个独立视角

1. **Karpathy 视角**：LLM 是 wiki 的维护者，"I rarely touch the wiki directly"。这意味着 LLM 的判断错误会直接固化进知识库，无人审校。

2. **GBrain 视角**：`Compiled Truth` 设计为有新证据时整体重写，Timeline 只追加不修改。这看似严谨，但若某次写入包含被注入的错误信息，该错误会作为"最佳理解"覆盖掉之前的正确内容。

3. **Agent安全体系视角**：供应链攻击的入口是 Skill。但若攻击者能控制一个 Agent 读取的网页、邮件或文档（外部内容均可能含 Prompt Injection），则知识库的写入行为本身就是一个放大器。

### 隐藏关联

> **知识复利 = 风险复利 × 污染密度**

GBrain 的 Brain-Agent Loop 在每次对话后将新知写入。若攻击者在某次"信号"（网页/邮件/推文）中植入污染信息，该信息经 Agent 提炼后写入 Compiled Truth，随后在未来所有对话中被读取并参与决策——这与金融领域的"坏账资产化"机制高度相似。

做梦机制（见 [[知识管理/GBrain-世界知识脑#做梦循环]] 和本 wiki 的 [[知识管理/个人知识库编译器模式]]）在夜间批量处理遗漏实体，若污染源在处理前未被清除，做梦只会放大污染范围。

## 实践含义

### 知识库需要"免疫系统"，不只是"防火墙"

当前 Agent 安全体系的设计逻辑是**边界防护**：在危险操作执行前插入人工审批。但知识库污染攻击的特点是：

- **单次写入无害**（看起来只是加了一条记录）
- **累积效应有害**（错误信念在多次引用后被强化）
- **难以归因**（几十次对话后很难追溯哪次写入引入了错误）

这要求知识库设计除边界防护外，还需要：
1. **写入溯源**：每条 Compiled Truth 更新必须记录信息来源（网址/对话ID），类比 GBrain 的 Timeline 设计。
2. **定期知识审计**：类比 Agent 安全审计员，设计一个独立 Agent 专职质疑现有知识，而非增量积累。
3. **可疑来源隔离**：外部信号（尤其是公开网页、陌生人邮件）写入的知识应打"待核查"标记，不立即参与核心决策。

### Karpathy 原则的安全推论

Karpathy 主张"用持续约束产生可积累的产物"。从安全角度，这个约束不仅应施加在 Agent 的行为上（CLAUDE.md），也应施加在 Agent 的知识更新上：

> LLM 天然倾向于接受并整合新信息；需要用外部机制质疑知识的来源可靠性，而非寄希望于 LLM 自身的批判性判断。

## 一句话总结

知识库的复利价值和复利风险来自同一套机制。在 Agent 安全体系中，知识库写入权限和命令执行权限应该被同等对待。
