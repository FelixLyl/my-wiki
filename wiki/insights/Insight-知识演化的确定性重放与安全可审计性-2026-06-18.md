# 知识演化的确定性重放与安全可审计性

## 三层碰撞

**HyperFrames** 的核心设计哲学是确定性：同一 HTML 输入，任何时间渲染，永远产出相同帧序列。这不只是工程约束，而是一种可审计性声明——任何人可以拿到源文件，独立验证输出，供应链无法静默篡改渲染结果。

**GBrain** 用"Compiled Truth + Timeline"双结构管理知识：顶部是随证据更新的当前理解，底部是只追加不修改的证据链。这一结构本质上也是确定性设计——timeline 提供了从原始信号到当前结论的完整推导路径，Compiled Truth 可以被重新推导验证。

**OpenClaw安全体系** 的零信任原则要求"操作可逆、操作可审计、人在回路"。但这三条规则只解决了执行层的安全问题，没有解决**知识层的安全问题**：Agent 的"世界观"（存储在 GBrain / wiki 中的知识）本身是否可以被审计和验证？

## 核心洞见

**知识系统的安全审计依赖"知识帧"的确定性可重放。**

当前 Agent 安全体系的盲区在于：供应链攻击、Prompt Injection 和恶意 Skill 最终的损害可能不只是"执行了一条危险命令"，而是**悄悄污染了 Agent 的知识库**。被污染的 Compiled Truth 会以"合法知识"的身份参与后续决策，这种损害是无声、累积、难以发现的。

HyperFrames 确定性渲染的逻辑给出了一个类比：如果知识编译过程是"给定相同 raw 输入，永远产出相同 wiki 文章"，那么知识库的任何异常就可以通过"重放编译"被检测出来——这正是 wiki-compiler 的幂等防重模式（[[幂等防重模式]]）的安全含义，而不只是效率含义。

## 结构启示

这一碰撞揭示了两个可操作的推论：

1. **知识完整性校验可以纳入做梦机制**：健康检查不仅检查孤儿页、死链，还应随机抽取 N 篇文章与其 raw 来源比对，验证编译结论是否与原始素材一致。这是 GBrain Timeline 的审计逻辑 × SecureClaw 定期巡检的知识层移植。

2. **Timeline 是知识系统的操作日志**：GBrain 的 Timeline 结构与 git commit history 同构——它保证了 Compiled Truth 的推导路径可溯源。wiki-compiler 目前依赖 `_log.md` 记录入库日志，但缺少文章级别的"修改原因"记录。若每次文章更新附带"触发素材 + 变化摘要"，知识库就获得了类似 Timeline 的审计能力。

## 一句话核心

> 知识系统的确定性不只是效率工具，更是安全工具：可重放的编译过程是抵御知识污染攻击的底层防线。
