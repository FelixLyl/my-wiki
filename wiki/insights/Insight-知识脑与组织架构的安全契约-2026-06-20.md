# 知识脑与组织架构的安全契约

## 核心洞见

GBrain 建立了一个知识复利循环，CCGS 建立了一套组织角色体系，OpenClaw 安全体系建立了运行时防线。三者在表面上服务不同目标，但有一个共同的隐含前提被各自独立地提出：**知识的可信度与访问者的角色身份必须同时被管理，否则系统的复利会反向加速风险扩散。**

GBrain 的 Brain-Agent Loop 每次写入都在扩大知识库。CCGS 的 49 个 Agent 各自都有读写权限。OpenClaw 安全体系要求零信任和最小权限。当三者同时运行时，问题变得清晰：**谁写入知识脑，决定了整个系统的信任边界。**

## 三层视角的交叉

### 1. 知识写入主体问题

GBrain 中，任何参与 Brain-Agent Loop 的 Agent 都可能写入 Compiled Truth。CCGS 的三层组织架构（Directors/Leads/Specialists）规定了角色权限的垂直分层，但这套层级仅在任务委派层面定义，并未明确约束对共享知识库的写入权。

当一个 Tier 3 Specialist 执行了某个错误操作并将"经验"写入共享 Brain 时，整个系统的知识基础就被污染了——而这个污染会随每次循环复利放大。

### 2. 零信任在知识层的缺位

OpenClaw 安全体系的零信任原则聚焦于运行时操作（`rm -rf`、防火墙修改），但没有延伸到知识写入。**"不信任任何输入"应当包括：不信任任何 Agent 的自主知识写入。**

CCGS 的 Hooks 机制（12 个自动化校验）给出了一个可借鉴的结构：在操作节点插入强制校验。同样的逻辑可以用于知识写入：每次 Brain 写入触发一个"知识质量 Hook"，由更高层级 Agent 或 human-in-loop 审批重要知识变更。

### 3. 组织架构的知识权限映射

CCGS 的层级结构天然适合映射到知识写入权限：

| 层级 | 操作权限 |
|------|----------|
| Tier 1 Directors | 可重写 Compiled Truth（顶层知识） |
| Tier 2 Leads | 可追加 Timeline + 新建知识页 |
| Tier 3 Specialists | 只读 + 提交"知识草稿"待审批 |

这套映射不需要额外的访问控制基础设施，只需在 Agent 的 System Prompt 中明确写入权限边界，再配合一个简单的知识 Hook 做拦截。

## 可操作的设计原则

**知识写入权限应与角色层级绑定，而非与执行权限共享。**

执行权限关注操作可逆性（trash > rm），知识权限关注信息可信度（谁的写入算数）。两者分离管理，各自有自己的审批路径。

在实践中，这意味着：
- 高频写入（Specialist 级操作记录）存入 Timeline，标注来源 Agent 和置信度
- 低频但重要的知识更新（Compiled Truth 重写）需要 Director 级确认或 human-in-loop
- GBrain 的夜间做梦循环可以扮演"知识审计员"角色：重新审视白天所有写入，决定哪些值得提升至 Compiled Truth
