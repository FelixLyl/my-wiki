# 规格即安全边界的外显化

## 洞见

三篇风马牛不相及的文章指向同一个底层结构：**控制 AI 行为风险的有效路径，不是在运行时检测异常，而是在行动前把"允许做什么"写成可读的外部工件。**

[[OpenClaw-Agent安全体系]] 的零信任原则要求对高危操作强制插入人工审批节点，其本质是将"可执行范围"具体化。[[OpenSpec规范]] 的做法是在写代码前先把变更边界固化为 proposal + specs + design + tasks 四份文档，AI 只能在这个工件链内行动。[[Andrej-Karpathy]] 的知识库理念则将 LLM 的产出约束在 wiki 格式和双链结构之内，用持久化工件替代不可追溯的聊天历史。

三者共享同一个操作逻辑：**把隐式授权显式化。**

## 隐式授权的风险

安全体系面对的核心威胁——Prompt Injection、Agent 越权——本质上都是隐式授权被绕过或伪造。当 Agent 的行动边界只活在 Prompt 里时，边界是可以被后续输入篡改的。当需求只活在聊天历史里时，AI 会选一种解读静默执行，而无需征得人类同意。Karpathy 对 LLM 编码缺陷的观察（"天然倾向于选一种解读静默执行"）和安全研究者对 Prompt Injection 的描述几乎是同一件事的两个侧面。

## 规格文件作为安全基础设施

OpenSpec 的 `tasks.md` 和 `design.md` 不只是开发效率工具——它们是行为契约。AI 在实现代码前必须和人在这两份文档里对齐，相当于每次操作前的静态分析。这和 openclaw-ops-guardrails 在执行高危命令前触发拦截的逻辑是等价的：两者都是在动作发生前插入一个"边界在哪里"的确认步骤。

差别在于：安全工具做的是运行时检测（看操作类型），规格工件做的是设计时约束（看操作意图）。设计时约束更根本，因为它在行为发生前就排除了不对齐的路径。

## 知识库作为最大的规格文件

Karpathy 的 wiki 模式在这个框架里呈现出新的意义：个人知识库是对"我认为什么是正确的"最大粒度的显式化。Agent 在这个 wiki 里写作时，受文章格式、双链结构、frontmatter 约束，这些约束扮演的角色和 OpenSpec 的工件链是等价的——都是把允许产出的形态提前锁定。

一个没有格式约束的 LLM 产出是不可审计的。一个在 wiki 结构内写作的 LLM，每次产出都是可 diff 的工件，也就是可审计的。

## 推论

这三个系统揭示了一个通用范式：**高权限自主系统的安全控制，最终归结为工件的可读性和不可旁路性。** 工件越清晰，边界越显式，AI 能绕过约束的空间越小。

这反过来提示了安全体系设计的一个盲点：如果一个系统缺少规格工件（只有 Prompt 驱动），那么再强的运行时防护也是不完整的——因为防护只能拦截已知的危险操作类型，无法验证操作意图是否与原始授权对齐。
