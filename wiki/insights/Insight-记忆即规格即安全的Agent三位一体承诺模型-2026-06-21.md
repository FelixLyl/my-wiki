# Insight：记忆、规格、安全是 Agent 行为承诺模型的三个投影

## 核心命题

[[Claude记忆机制]]、[[OpenClaw-Agent安全体系]]和[[OpenSpec规范]]表面上分属"工程效率"、"系统安全"和"记忆持久化"三个方向，但它们共同指向同一个底层缺位：**Agent 的行为承诺在执行前、执行中、执行后三个阶段都缺乏结构化载体。**

## 三个投影

**OpenSpec** 解决的是执行前的承诺：在 AI 动手写代码前，用 proposal/design/tasks 三份文件把"做什么"锁定为可追溯的工件链。其核心洞见是 requirements 只活在聊天历史里会导致失控。

**Claude-Mem** 解决的是执行后的承诺：在 Session 结束后自动写入观测记录，使下次 Session 能够感知"做了什么"。分层渐进披露（摘要 → 时间轴 → 完整详情）是为了在 Token 效率和信息完整性之间取得平衡。

**OpenClaw 安全体系**解决的是执行时的承诺：零信任原则要求所有危险操作在执行前强制二次确认（openclaw-ops-guardrails），供应链扫描（skill-vetter）在安装前建立防线。其本质是**将人工审批插入 Agent 的危险操作路径**，而非寄希望于 Agent 自身判断。

## 结构融合的可能性

三者目前各自独立运作，但它们的作用层可以形成一条完整的承诺链：

```
[执行前] OpenSpec tasks.md  →  变更意图的结构化承诺
         ↓
[执行时] 安全护栏拦截       →  高危操作的二次确认节点
         ↓
[执行后] Claude-Mem 观测写入 →  实际执行的语义摘要留存
```

如果三层打通，就能回答 Agent 行为审计的三个核心问题：**该做什么（规格）、实际做了什么（记忆）、有没有越界（安全）**。当前三者各自回答一个问题，但没有任何机制将三层的答案对比校验。

## 缺位识别

当前最明显的缺位是**规格与记忆之间的偏差检测**：OpenSpec 的 tasks.md 记录了计划，Claude-Mem 的 observations 记录了执行，但没有任何工具自动对比"计划偏差了多少"。这一缺位在 Agent 自主执行长任务链时风险最大，因为每一步的小偏差会在多跳之后累积成不可预测的结果。

## 推论

记忆系统的进化方向不是"存更多"，而是"存更可核验的"。当记忆条目能够对应到一条规格承诺，并附带安全审计的通过/拦截记录，Agent 的行为才真正进入可追溯、可回放的状态。在此之前，三套系统解决的是各自领域内的局部问题，而非 Agent 可信赖性的整体问题。
