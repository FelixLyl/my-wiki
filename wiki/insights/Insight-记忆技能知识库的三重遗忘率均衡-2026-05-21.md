# 记忆、技能、知识库的三重遗忘率均衡

三篇文章看似无关：一篇讲 Agent 如何跨会话记住事情，一篇讲 Skill 如何封装和分发能力，一篇讲知识库如何自我进化。但它们共享同一个底层问题：**AI 系统如何在"遗忘"与"保留"之间找到正确的均衡点。**

## 三种认知层的遗忘率

Agent 认知体系可以分为三个维度，每个维度有截然不同的遗忘率设计：

| 维度 | 代表系统 | 遗忘率策略 |
|------|----------|-----------|
| **记忆层**（会话轨迹） | lossless-claw 树状摘要、Claude记忆机制 | 衰减型：近期细节保留，远期压缩为要点 |
| **技能层**（能力封装） | OpenClaw Skill 生态、autoskills | 零遗忘：一旦编写，永久可用，跨 Agent 共享 |
| **知识层**（提炼沉淀） | wiki-compiler、GBrain | 主动蒸馏：做梦机制驱动，旧内容审视而非直接丢弃 |

这三个维度的遗忘率**刻意设计为不同**，且各有其原因。

## 遗忘率不对称的必要性

记忆层必须衰减：会话轨迹如果永久保留、等权传入上下文，Token 成本将随时间线性爆炸。lossless-claw 的树状摘要和 Claude记忆机制的渐进式披露都是对这一约束的工程化响应——**遗忘是 Token 经济学的必然要求，而不是设计缺陷**。

技能层必须零遗忘：一个已经验证有效的 SOP（比如 PRD→Issues 流程、代码质量审查规范），其价值与时间无关。self-evolving-skill 机制甚至允许 Skill 自我修复适配新环境，而不是被淘汰替换——**能力封装的价值来自可靠的不变性**。

知识层必须主动蒸馏而非被动积累：做梦机制的"灵感碰撞 + 健康检查"不是在"删除旧知识"，而是在**重新激活休眠的知识节点**，让已有内容在新的连接中产生增量价值。wiki-compiler V2 的零幻觉设计——断链时生成追踪卡而非捏造内容——意味着知识层的"遗忘"是结构化的存疑，而非静默丢失。

## 三层错位是常见的系统设计失误

当开发者不加区分地对待这三个维度时，会产生典型的错位：

- **把会话记忆当作技能**：把临时上下文塞入 Skill 文件，导致 Skill 随会话漂移，失去跨 Agent 可靠性
- **把技能当作知识库条目**：把工具 SOP 直接入库，而不是先抽象为幂等的 Skill 单元再归档
- **把知识库当作记忆日志**：按时间顺序追加内容，而不按主题结构组织，最终变成无法检索的流水账

[[Insight-有状态积累与无状态复现是Agent工具的两极]] 已指出"知识层需有状态积累复利，执行层需无状态确定性可复现"。本文在此基础上补充：**知识层内部也存在分层——记忆/技能/知识库各自的遗忘率策略是整个认知体系稳定运行的隐性前提**。

## 均衡点的工程信号

如果三层均衡被打破，系统会发出可观测的信号：

- 记忆层遗忘过快 → Agent 在重复犯同类错误
- 技能层积累过多 → Skill 文件冲突、同类能力多头并存
- 知识层蒸馏不足 → 大量孤儿页面、wiki 健康检查报告劣化

这些信号本身可以成为触发相应维度修复的自动化条件——形成认知体系的**三层自愈闭环**。
