# 配置即知识基因

## 碰撞源

三篇风格迥异的文章在同一个深夜相遇：
- [[GBrain-世界知识脑]]：每次对话前读脑库、每次对话后写脑库，知识随时间复利积累；
- [[autoskills]]：一行命令扫描技术栈、自动安装最匹配的 Skills，为 Agent 生成 `CLAUDE.md`；
- [[CLAUDE-md配置方法论]]：在项目根目录植入"思维逻辑"，让 AI 从被动执行变为主动判断。

表面上，GBrain 是记忆系统，autoskills 是工具链自动化，CLAUDE.md 是行为声明。但三者背后有一个共同的隐喻：**配置是知识的基因编码。**

## 洞见

生物的行为由基因决定，但基因本身不执行行为——它是编码在 DNA 里的规则，由环境触发。Agent 系统里的"基因"是配置文件：

- **GBrain** 的 brain 页面是 Agent 的"世界模型基因"。Compiled Truth 是经过淘汰的最佳理解，Timeline 是证据的有序积累。每次循环都在重写顶部、追加底部——这正是基因表达的逻辑：表现型更新，但遗传记录不删除。

- **CLAUDE.md** 是 Agent 的"行为基因"。三层结构（决策层 / 执行层 / 进化层）声明了遇到不同情境时该激活哪套反应机制。把 4 条黄金准则或 Karpathy 准则写进去，Agent 每次执行都会"读取"这段 DNA，成本为零。

- **autoskills** 则是"基因工程师"：它从项目的表现型（package.json、框架文件）反推出应该安装的基因片段（Skills），再注入到配置文件（CLAUDE.md）里。这是一个反向工程的过程——从行为推导基因，而不是从基因预测行为。

## 三者的关系

```
autoskills
  → 识别项目 DNA（技术栈）
  → 写入行为基因（Skills + CLAUDE.md）

CLAUDE.md
  → 运行时激活行为基因
  → 决定 Agent 如何感知-判断-执行

GBrain
  → 持续更新世界模型基因（brain 页面）
  → 每次循环都让 Agent 携带更丰富的上下文出发
```

三者覆盖了"基因"的三个层次：工具链基因（autoskills 注入）、行为基因（CLAUDE.md 声明）、记忆基因（GBrain 积累）。一个完整的 Agent 系统需要三层同时就位。

## 推论

**配置文件的密度决定了 Agent 的起点质量。** 一个空 CLAUDE.md 的 Agent 和一个精心调试过 CLAUDE.md 的 Agent，执行同一个任务的路径会完全不同——前者每次都从头摸索，后者带着经过蒸馏的判断规则出发。

这与生物进化的逻辑一致：个体不需要重新学会如何呼吸，因为这已经被编码进基因。Agent 也不应该重新学会"遇到 bug 先找根因"，这应该已经写在它的 CLAUDE.md 里。

**autoskills 揭示了配置的可逆向工程性。** 技术栈可以被读取，最优 Skills 可以被推断，CLAUDE.md 可以被自动生成。这意味着"为 Agent 编写最优基因"这件事本身，也可以被另一个 Agent 承接——配置的自动化是 Agent 系统进化的下一个前沿。

**GBrain 的 Compiled Truth 结构是知识进化的最小可行模型。** 顶部重写（表现型更新）+ 底部追加（遗传记录）的模式，可以推广到任何需要"既能更新又能溯源"的知识结构——包括 CLAUDE.md 本身。
