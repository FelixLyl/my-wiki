# Insight：静态人设与动态人格图谱的分野

## 碰撞背景

The Agency 以"组建梦之队"为比喻，为每个 AI Agent 定义了固定的人格文件：专业领域、声音风格、交付物清单。这是当前 Agent 工程的主流做法——人格在部署时写定，此后不再变化。

Graphify 的核心主张与此形成对比：代码库理解不能用扁平文档表达，必须用**实体 + 关系**的图结构来承载，因为调用关系、模块依赖、论文符号到代码变量的映射，都是关系而非文本。

自学习复盘模式更进一步：Agent 每次被纠正，都会将"错误描述 + 正确做法 + 适用场景"写入知识卡片，后续任务主动调用——这是一个持续更新的行为关系网络。

## 核心洞见

三者的碰撞揭示了 Agent 专业化的两条路线：

**路线 A：静态人设**（The Agency 当前模式）
- 人格在部署时一次性写定
- 优点：可预期、可审计、跨工具复制简单
- 缺点：专业化是初始状态，不随任务积累加深

**路线 B：动态人格图谱**（Graphify × 自学习复盘的延伸）
- Agent 维护一个关于"自己管辖系统"的实体 + 关系图谱
- 每次错误纠正在图谱中新增"反例节点"及其关系边
- 每次成功操作强化特定路径的权重
- 人格文件变成图谱的入口声明，而非全部定义

两条路线的本质差异不在于"静态 vs 动态"，而在于**知识拓扑的维度**：静态人设是一维的（线性文档），动态人格图谱是多维的（关系网络）。

## 为什么图谱拓扑更适合"专家"

真正的专家不只有知识，还知道知识之间的**路径**：给定一个问题，专家知道从哪里开始、走哪条路、绕开哪个陷阱。这恰好是图遍历，而非文档检索。

自学习复盘模式的知识卡片（错误 → 纠正 → 适用场景）天然是三元组：正好是图谱的基本单元。当积累足够多的卡片后，Agent 的行为网络就成为一张可遍历的"经验图谱"，而非一堆分散的文本片段。

The Agency 的飞书集成专家 Agent，如果配备了这套机制，其"飞书专业化"不再只是初始 Prompt 写得好，而是随着项目推进、错误纠正，逐渐形成一张关于"飞书 API 调用路径 + 典型错误 + 平台限制"的稠密知识图谱。

## 尚未解决的问题

- 动态人格图谱的更新频率与审计成本之间如何平衡？（参见 [[OpenClaw-Agent安全体系]] 中的代码安全扫描约束）
- 跨 Agent 的图谱如何合并？The Agency 有 70+ 个 Agent，各自的经验图谱存在大量重叠边
- 图谱规模增长后，推理延迟是否会影响实时任务响应？

## 实践方向

最小可行路径：在 The Agency 的 Agent 文件中增加一个 `memory_graph` 字段，指向一个持久化知识卡片库。不需要重构人格系统，只需让已有的自学习复盘机制与已有的人格文件产生关联。这比"重构 Agent 为图谱"工程量小一个数量级，但可以验证核心假设。
